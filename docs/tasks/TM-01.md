## 4. Item C feasibility (CriticAgent with tools) — installed `@google/adk` 2.2.1

- `FunctionTool` exists (`dist/types/tools/function_tool.d.ts`): `{ name, description, parameters: zod v3/v4 object
  | Schema, execute(input, ctx) }`.
- Output schema + tools: `dist/esm/agents/llm_agent.js:880` — when `outputSchema` is set AND tools exist, ADK uses the
  native path only if `canUseOutputSchemaWithTools(model)`; `dist/esm/utils/output_schema_utils.js:12` returns
  `VERTEX_AI && isGemini2OrAbove`. With `vertexai:true` and `gemini-3.5-flash` that is **true**, so ADK sends tools and
  the response schema in the same request (Gemini 3 supports function calling + structured output per adk.dev:
  "only supported by specific models, including Gemini 3.0; for other models ADK falls back to a `set_model_response`
  function tool … which may not work reliably"). Caveat: `canUseOutputSchemaWithTools` reads `getGoogleLlmVariant()`,
  i.e. the process-wide `GOOGLE_GENAI_USE_VERTEXAI` env, not the `Gemini({vertexai:true})` instance — if that env is
  unset on Cloud Run the fallback tool path is taken instead. Must be checked in a spike; it was not needed for R-08
  because R-08 uses `generateContentConfig.responseJsonSchema`, not `outputSchema`.
- Also unverified on live: `responseJsonSchema` + `thinkingConfig {thinkingLevel: LOW}` + tools in one request on
  `gemini-3.5-flash` at `asia-southeast1` (its probed location; `global` is not what regions.yaml says for flash).
- Hard rules touched: #10 (the gate stays plain code — a Critic that *calls* the gate as a tool is fine, a Critic
  whose *verdict* overrides the gate is not), #7 (the Critic sees only `ProposalWire` + dated evidence summaries,
  never thread ids, device ids or names), #2/#3 (nothing new stored unredacted), #5 (location from regions.yaml).
  CLAUDE.md has no "Critic prompt injection pattern" — the brief's dependency is invented; the only pattern in the
  repo is R-08's InstructionProvider rule (`proposal-agent.ts:95-98`).
- Realistic estimate with a Task-0 spike, flag `CRITIC_ENABLED` default off, fallback to gate-only on any error,
  tests, tech-lead + QA gates and a live run: **10–14 h agent time + 2 fix rounds**, on the critical path (it sits in
  `generateProposal` between the gate and the store).
- Lower-risk variants: (a) **read-only tool agent + no-tools JSON step** — a Critic `LlmAgent` with `check_evidence`
  and `get_constraints` tools and *no* schema produces a short critique text; a second no-tools call (or plain code)
  turns it into `{verdict, reasons[]}`; the gate's result is still the only thing that blocks. (b) **Critic as
  `beforeModelCallback`-free plain second opinion**: same prompt, no tools, inputs pre-computed by code
  (gate checks + constraints inlined); that is "a second model opinion", not tool calling, but 3–4 h and no new API
  surface. (c) Skip C; spend the hours on the evidence pack.
