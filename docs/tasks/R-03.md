## Decisions (resolved by the team — verified, not guessed; see rationale)

1. **Segment PUT contract — RESOLVED.** Reuses R-02's existing `requireDevice` guard exactly
   (`lib/http/guard.ts`: `Authorization: Bearer <device_token>` + `X-Device-Id` header — already
   documented there as "used by... later, segment/heartbeat uploads"). Adds:
   `PUT /api/v1/segments/{device_id}:{seg_id}`, `Content-Type: audio/webm;codecs=opus`,
   `X-Segment-Start-Ms` / `X-Segment-End-Ms` (device epoch ms) / `X-Segment-Sample-Rate` headers,
   raw Opus/WebM bytes as the body (size-capped, reject oversized with 413). Idempotent on
   `seg_id`: a repeat `PUT` returns `200` without a second transcribe call (R-04's job; R-03 defines
   the shape and a contract test, R-04 implements the transcribe path).
2. **Silero VAD licence — RESOLVED, all clear.** `@ricky0123/vad-web` (ISC), the Silero VAD ONNX
   weights (MIT, snakers4/silero-vad), `onnxruntime-web` (MIT). No copyleft; safe for the public
   repo (hard rule #8). It's local signal processing, not a call to a hosted AI provider, so it
   doesn't trip hard rule #1. All three vendored into `public/`, no CDN. Cite in
   `THIRD_PARTY_NOTICES.md`.
3. **Container format — RESOLVED: WebCodecs `AudioEncoder` (opus) + `webm-muxer` (MIT) → WebM/Opus.**
   Chosen over `MediaRecorder` because VAD (not a fixed timeslice) decides segment boundaries, and
   over Ogg/Opus because Gemini's audio-input docs list `audio/webm` and `audio/opus` as accepted
   inline MIME types — no server-side transcode needed before R-04's Transcribe call. Caveat carried
   into R-04: verify the exact accepted MIME list on Vertex's `gemini-3.5-transcribe` specifically
   (the check so far covers the public Gemini API's audio-understanding docs, not confirmed
   identical on Agent Platform/Vertex).
4. **`GET /api/v1/capture/config` — RESOLVED, adding it.** Device-authenticated (same
   `requireDevice` guard), returns `{ consent_complete, opening_time, closing_time, timezone }`
   from the outlet doc. Keeps the browser off Firestore directly (hard rule #6).
5. **Offline queue — RESOLVED, no question.** The spec (§5 step 5) already says in-memory only for
   MVP (~10 min, oldest dropped and counted); the IndexedDB/AES-GCM queue is explicitly P1. §8's
   "capture keeps queuing" at the token ceiling refers to this same browser-side queue.
