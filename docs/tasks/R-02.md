# R-02 — Data + login + roles (plan)

**Spec:** web spec §2, §3, §6.2, §6.4, §6.5 · backlog R-02 · CLAUDE.md §2 hard rules.
**Depends on:** R-01 (skeleton, regions loader). **Blocks:** R-03 (device token), R-04.

## Goal
The agent-buildable, non-UI slice: Firestore schema v0 + zod, Firebase Admin server
init, server-side RBAC guard, device pairing + staff PIN auth, Google sign-in wiring,
a minimal `/pair` page, and the seed script (pilot vs demo).

## Decisions (ask Rangga to ratify)
- **PIN hashing = `bcryptjs`** (pure-JS, no native build → clean Cloud Run buildpacks +
  runs in the sandbox test env). Not an AI dep, so allowed under hard rule #1. Alternative
  was `argon2` (stronger, but native bindings). **RATIFY?**
- **Device token = opaque random secret** (32 bytes, base64url), stored **hashed** on the
  device doc, presented as `Authorization: Bearer` on segment/heartbeat uploads. Chosen
  over a Firebase custom token because the spec wants a *long-lived* token and custom
  tokens expire in 1 h. Revoke = set `revoked:true` (a seed/script command). **RATIFY?**
- **Staff PIN session = Firebase custom token** minted server-side via Admin
  `createCustomToken(staff_id, claims)` (spec §3: "custom tokens for … staff PIN
  sessions"). The browser exchanges it for an ID token via the Firebase client (R-03/R-07).
- **Pairing code = 6 digits stored in plaintext** on the device doc with a 10-min expiry,
  queried by equality, single-use (cleared on pair). Low entropy anyway; hashing would
  block the lookup. Mitigated by short TTL + single-use + (later) per-IP rate limit.
  **RATIFY?**
- **Roles:** user/staff docs use `owner|supervisor|staff`. Token-claim/RBAC principals add
  `device` (the shop phone) → `owner|supervisor|staff|device`.

- `lib/firestore/schema.ts` — zod + TS types for every §6.4 collection. Real now:

  `windows, threads, questions, corrections, sop_versions, proposals, constraints,

  `staffPinLogin`, `linkGoogleUser`, `authenticateDeviceToken`.
- `lib/http/errors.ts` — `AppError` hierarchy + `handleApiError` (error-handling skill).

- `app/pair/page.tsx` — minimal client form → posts code → stores device token.

- `pin.test.ts` — hash/verify round-trip; format rejects non-4-digit; 5 wrong → locked 15

- `services.test.ts` — `pairDevice` (valid/expired/used/wrong code), `staffPinLogin`
  (happy/locked/wrong-pin/unpaired-device), `linkGoogleUser` (email match/no match).

## Hard rules honored
- No non-Google AI SDK/key (bcryptjs + firebase-admin are infra, not AI).
- No audio persisted/logged: `segments` schema has no audio/base64 field; nothing here
  writes Cloud Storage.
- Names only in `staff`: `audit_log`, claims, and every other doc store role/`staff_id`,
  never a name.
- Every route checks role + outlet on the server via `requireClaims` + `authorize`.
- Firestore closed to browsers: all access via routes; Admin creds server-only.
- No secrets committed: seed reads project from `--project` + env; prints code to stdout.

## Tech Lead findings applied (task #4)
- **#1 email_verified:** `verifyIdToken` now surfaces `email_verified`; the Google
  sign-in path rejects an unverified/absent email before linking a role
  (enforced in `linkGoogleUser`, covered by services.test; the session route
  passes the flag through). An unverified Google email can never gain outlet access.
- **#2 localStorage device token — ACCEPTED design:** the long-lived device token
  stays in `localStorage` on the dedicated, physically-controlled shop phone (spec
  §3 MVP). It is opaque, stored only hashed server-side, revocable, and grants only
  device permissions — never owner/supervisor/staff access. At-rest hardening
  (WebCrypto non-exportable key) rides with the P1 encrypted queue (§5). Documented
  with a code comment in `app/pair/page.tsx`.
- **#3 staff-name normalization:** added `normalizeStaffName` (trim + casefold +
  collapse whitespace) and a `name_key` field on `staff`. The seed writes both the
  display `name` and `name_key`; `findByName` matches on the normalized key so
  casing/whitespace in the typed name still resolves. Covered by staff-name.test +
  seed.test.
- Gates after fixes: typecheck ok · lint ok · vitest 89/89 · next build ok.
